# 长生录 / Immortal Path

一款完全离线、单机运行的文字卡片式修仙 Roguelite。玩家会经历一世又一世的修行、突破、衰老与死亡；人物会轮回，世界却会继续演化，最终形成属于自己的修仙史。

## 技术栈

- Vue 3、TypeScript、Vite
- Pinia、Vue Router
- Dexie.js + IndexedDB 本地持久化
- Vitest 核心逻辑测试

项目不包含后端、在线 API、登录或云数据库。依赖安装完成后，游戏运行不需要联网。

## 安装、运行与构建

```bash
npm install
npm run dev
npm test
npm run build
```

## 游戏玩法

1. 选择出身、灵根、五维属性与多个天赋，或分别交给天意随机生成。
2. 第一世选择有限；后续转世可在轮回殿购买下一世的择命权限。
3. 选择主道与兼修道途、挑选契合自身的功法，再以闭关、历练、悟道、炼体、游历或休养推进真实年岁。
4. 每次年度行动会结算修为、功法、状态、资源、人生事件与命运进度；危险历练也可能带回伤势。
5. 修为、功法、资源、状态与破境准备全部满足后才能手动突破。成功会进入下一境界并提高寿元，失败可能倒退、受伤、折寿甚至死亡。
6. 死亡后查看完整生平，并选择接管存活的成年后代，或进入轮回殿重新投胎。
7. 人物可以更替，但世界年份、宗门状态、旧家族、旧后代和世界历史不会重置。

开发模式可在“设置 → 天道调试台”快速增加资源、生成后代、解锁天赋、查看隐藏身世或进入轮回殿。

## 项目结构

```text
src/
├─ core/          # 修炼、创建、突破、掉落、轮回、时间、世界、随机与存档规则
├─ data/          # 境界、物品、天赋、出身、灵根、事件与掉落表
├─ models/        # TypeScript 领域模型
├─ stores/        # Pinia 流程协调与自动保存
├─ components/    # 角色创建、角色状态、最近纪事与奇遇选择
├─ views/         # 八个路由页面
└─ router/        # Hash 路由，兼容本地静态运行
```

## 核心系统

- 时间以月为内部单位，界面展示年/月；没有现实倒计时。
- 43 个境界覆盖凡人、炼气直至渡劫；每个大境界都有独立基础寿元。
- 64 个随机事件、22 件物品、23 个先天天赋、8 个后天天赋与 8 种出身均为配置驱动。
- 掉落由境界奖池、气运权重、福缘模式与稀有/极品双保底共同决定。
- 世界模拟会在时间流逝时生成大事、改变宗门势力并推进非玩家后代年龄。

## 第二阶段：择命与血脉

- 第一世开放五种凡俗出身，可手选五、四、三、双灵根和十五种基础天赋；随机灵根仍可能获得稀有品质或变异属性。
- 每个出身分别定义基础属性、属性上限、自由属性点、初始资源与玩法修正；天赋点使用独立配置。
- 天赋点允许搭配任意数量的合法天赋；随机天赋获得一点额外价值预算。
- 后代由父辈属性、遗传权重、随机波动与血脉共同生成，并作为真实世界人物保存。
- 血脉延续会接管既有后代，不能重新捏人，但会继承部分家族灵石、物品和血脉标记。
- 轮回点用于购买下一世的天赋预算、属性上限、高阶天赋/灵根/出身权限和前世记忆，不再永久线性增加属性。
- 高级天赋同时受下一世选择权限和永久因果条件限制。

### V2.1 属性与灵根修订

- 出身只影响基础属性、潜力、自由属性点、初始资源与特殊修正；天赋预算改为独立配置。
- 第一世自由属性点为：农户 50、猎户 45、商贾 35、书香门第 35、神秘弃婴 45。
- 灵根数量表示广度与总吸收效率，品质和变异表示专精方向，不再使用线性品阶。五灵根总修炼效率 ×1.35，四灵根 ×1.27，三灵根 ×1.18，双灵根 ×1.10，单灵根 ×1.00；灵根越少，同系功法专精越高。
- 灵根补偿自由属性点为：五灵根 +0、四灵根 +1、三灵根 +3、双灵根 +5、单灵根 +6。
- 雷、冰、风、暗、光是可组成单/多灵根的变异元素；`PURE` 与 `HEAVENLY` 是品质。极稀有的五行天灵根总修炼效率为 ×1.60。
- 第一世手选仅限标准五行的五、四、三、双灵根；后世可分别解锁单灵根、变异元素、纯净与天品品质。随机生成不受这些手选权限限制。
- 功法契合与大境界突破分别通过统一的灵根契合度、突破修正接口计算。
- 角色新增 `statPotential` 和带时间、原因的 `statHistory`；奇遇、突破、失败与衰老统一通过属性修改机制处理。
- 普通成长受潜力限制，明确标记的特殊效果可以突破潜力。

## 第三阶段：大陆、道途与寿元

- 新游戏由 Seed 确定性生成随机大陆、时代、强度、3—5 个相容世界特质、修炼环境与五道分布。
- 道修、剑修、体修、魔修、鬼修拥有独立成长资源和事件；主道一世固定，并可兼修一条副道。
- 寿元由境界、体魄、天赋、体修与命数共同计算，暮年会产生衰老影响；大境界突破会重新结算上限。
- 肉身死亡后先进入选择状态。只有血脉延续或轮回转世才结算遗产、轮回点和人物志；转修鬼道会延续原人物，不复制家产。

### V3.1 后天灵根、功法契合与后天天赋

- `spiritualAptitude` 明确区分不可覆盖的先天灵根与后天灵根；后者记录元素、纯度、稳定性、来源和获得时间。
- 后天灵根可由天材地宝、雷劫淬体、秘境传承、血脉觉醒、魔道夺灵和轮回残留六类机缘获得，并可逐步提纯、稳固。
- 十种元素分别积累成长；完整五行根基会显示均衡度，偏科过重会形成失衡。
- 24 门功法覆盖标准五行、变异元素、复合元素与五条道途。契合度拆分为灵根、道途、悟性、天赋、世界和其他状态，并动态限制功法等级。
- 缺少对应灵根通常意味着低契合和高风险，并非一律禁止；体修、剑修、魔修和鬼修各有不同的低灵根依赖规则。
- 五行归一、剑心通明、百战之躯、九死一生、大器晚成、魔心无垢、逆天改命、天眷之人只能在游戏过程中按数据条件觉醒，不能在创建角色时购买。
- 后天天赋会写入当世时间线和最终人物志；指定因果只在真正结算死亡后开放下一世天赋。

### V3.2 人生事件、因果与命运线

- 新增独立人生事件模块，按年龄、境界、道途、灵根、天赋、属性、世界特质、历史标签与冷却筛选事件池；跨年时按概率和动态权重触发，不会每年强制弹窗。
- 首批 40 个人生事件覆盖凡人、修仙初期及中后期，每个事件均提供至少三个选择，结果可改变属性、修为、灵石、功法、后天灵根、后天天赋、道途资源与因果标签。
- 「人生」页面展示完整时间线、重要经历、因果标签和命运线进度；重要度 3—4 的节点会进入永久人物志。
- 剑道传奇、五行大道、逆天改命、魔道巨擘与长生之路会依据真实经历形成，并影响事件权重、此生评价、轮回点与后世解锁。
- 死亡总结保存姓名、享年、境界、道途、命运成就与重要经历；转修鬼道仍不会提前结算遗产、轮回点或最终人物志。

### V3.3 修炼循环、行动与突破

- 新增闭关、历练、悟道、炼体、游历、休养六种年度行动；玩家主动决定未来一至五年的修行方向。
- 闭关会增长修为、功法经验与破境准备，也可能顿悟、突破功法或遭遇心魔；修为圆满只会进入瓶颈，不再自动升级。
- 历练会按照世界资源与危险度、境界和道途生成灵药、妖丹、炼体材料、魂晶、灵石及伤势；悟道会推动元素、剑意、魔道领悟和后天天赋条件。
- 肉身拥有炼皮、炼肉、炼骨、炼脏、换血、金身六个阶段；休养可逐步恢复伤势、心魔、气血和魂体稳定。
- 突破同时检查修为、主修功法等级、基础资源、人物状态与突破准备，并综合灵根、悟性、气运、功法、道途、世界和状态计算成功率。
- 每次行动和突破都会写入独立日志，并与人生事件、因果标签、命运线和人物志联动。

## 存档说明

主存档位于浏览器 IndexedDB 的 `immortal-path-db` 数据库。修炼、历练、突破、事件、死亡与轮回选择后会防抖自动保存；设置页支持立即保存、导出 JSON、导入 JSON与删除重开。

产品版本为 V3.3，内部存档结构版本已升级至 8：

- Dexie 在打开数据库时迁移 V1 IndexedDB 主存档。
- 导入旧 JSON 时使用相同的兼容归一化流程。
- V1 角色、人物志与世界历史会保留。
- V1 已购买的永久属性等级会折算为轮回点补偿。
- V1/V2/V3 的旧 `rank` 灵根会转换为元素、品质、总修炼效率、专精效率与突破修正；旧天灵根和异灵根也会归一化。
- 旧版混用的稀有计数会迁移为稀有掉落计数；V4 起稀有事件与稀有掉落分别记录。
- V1—V7 会依次补齐随机大陆、道途、寿元、死亡结算、后天灵根、元素成长、功法、后天天赋、人生事件、因果、命运线、年度行动、修炼资源、人物状态、肉身阶段和突破历史字段；V8 可无损导出再导入。
